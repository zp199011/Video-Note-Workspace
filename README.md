# 字幕研究室 / Video Subtitle Lab

一个本地运行的 B站、抖音视频转写与知识沉淀工作台。

## 能做什么

- 输入 B站完整链接、BV 号、`b23.tv` 短链接，或抖音完整链接、分享短链接
- B站支持多 P；抖音按单条视频创建笔记
- 优先读取 B站播放器公开字幕和 AI 字幕
- 抖音默认由用户主动启动本地 FunASR，不把不存在的平台字幕伪装成原文
- 可选使用你自己的 B站 `SESSDATA` 读取需要登录的 AI 字幕
- 保留每段字幕的开始时间、结束时间和原文
- 支持字幕搜索
- 无字幕时可由用户主动启动本地 FunASR，生成可点击的时间轴
- 可由用户主动启动 CAM++ 说话人识别，生成独立的“说话人版”
- 长字幕 AI 任务会自动分块，失败时保留成功块并支持重试
- 支持完整操作日志、软删除回收站、Markdown 和 Obsidian 导出
- 支持“普通 API 整理全量资料 + Codex 核查合成”的可生长知识流程
- B站默认只获取当前 P 音频；抖音为了精确跳秒会缓存最高 720p 的本地视频
- 支持拖入本地视频或音频，作为平台读取失败时的可靠兜底
- 不把登录 Cookie 上传到第三方

## API + Codex 怎么用

1. 先确定本次处理的 P 范围和字幕轨道。短视频、单人讲解优先选`AI 润色版`；多人访谈可选`说话人版`；确实不需要润色时再选`原文`。
2. 说话人版会直接使用已经合并好的说话人段落。`未确定`或`多人`片段允许进入知识整理，不再要求每句话都识别出唯一说话人；但每一条源字幕都必须被覆盖，缺字或重复才会拦截。
3. AI 润色版按语义段落送入知识整理和结构生成，不再把每句时间轴当成一条独立知识。底层仍保留逐句对齐和源字幕 ID，方便回查原文。
4. 点击`1. API 整理资料`后，系统先做本地预检，在确认框中列出源字幕数、知识段落数、预计 API 请求次数和输入 tokens；只有你确认后才正式调用 API。开始后按钮会立即显示提交/整理状态，知识区持续显示百分比、当前分块、失败数和已用时；`生成日志`同步记录提交、开始、分块进度、完成或失败。系统逐块提取事实、观点、推测、方法、案例、问题和反对观点；失败时已完成块会保留，只重试失败块。
5. Codex 按钮旁会显示`可合成`或`资料不完整`。点击这个状态可查看 API 分块、知识段落、源字幕覆盖、快照版本以及具体失败分块/缺失字幕；只有完整度达到 100% 后，才能点击`2. Codex 核查并合成`。
6. Codex 先审计。`BLOCKED` 时只显示问题，不会生成正式内容；必须重新整理 API 资料，不能靠反复点 Codex 绕过审计。
7. `PASS` 后，`下载总 MD`和`写入 Obsidian`使用同一份 Markdown。总 MD 包含可点击证据、大纲、Mermaid 导图、行动项、争议点、候选原子笔记和锁定字幕。

未 PASS 时仍可手动下载草稿 MD，但文件顶部会明确标记 `status: draft` 和警告，同时禁止写入 Obsidian。

## 启动

需要 Node.js 18 或更高版本：

```bash
npm start
```

然后打开：

```text
http://127.0.0.1:4173
```

也可以换一个端口：

```bash
SUBTITLE_PORT=5173 npm start
```

## 重要限制

本地 ASR 不会自动启动。首次使用前安装依赖：

```bash
brew install ffmpeg yt-dlp
npm run setup:asr
```

随后在笔记里点击“本地 ASR”。B站只获取当前分 P 所需的音频流；抖音会缓存最高 720p 的视频，以便字幕时间戳控制本地播放器精确跳秒。媒体由 FFmpeg 转成 16kHz 单声道，再交给本机 `Paraformer + FSMN-VAD + CT-Punc`。首次运行会下载数 GB 以内的开源模型到 `data/models/funasr/`；模型、磁盘、网络和计算时间都不是零成本。默认用 CPU，实际耗时会写入任务记录，不承诺固定倍速。

下载过程使用 `data/tmp/asr/`，任务结束会清理；转好的 16kHz 音频保存在 `data/media/audio/`，抖音本地视频保存在 `data/media/video/`，供播放器、ASR 和说话人识别复用。ASR 轨道作为独立来源追加，不覆盖已有平台字幕。

说话人识别同样不会自动启动。点击“说话人识别”后，本机会用 `FSMN-VAD + CAM++` 得到说话人时间区间，再与当前字幕轨道做确定性时间重叠匹配；不调用 LLM。说话人版优先使用当前轨道完整的 AI 润色文字，润色不完整时整条轨道回退原文，不会混搭。相邻同一说话人的短字幕会按设置中的间隔和最大段长合并，原文、润色版和说话人版分别保存。当前版本不再提供翻译入口或翻译任务；历史笔记里的旧翻译字段仍会保留但不参与新流程。说话人名称可在说话人版上方点击修改。

说话人版上方提供“说话人”筛选，可以只查看某一位说话人的片段；它可以和文字搜索叠加，不会修改原文、润色版或完整说话人版数据。

模型完整下载后，worker 会优先使用 `data/models/funasr/` 中的本地快照，避免仅因模型别名解析需要联网。删除模型缓存后，下次运行会重新下载。

部分 AI 字幕会要求登录。可以展开网页里的“需要登录才能看的 AI 字幕？”，从自己浏览器的 B 站 Cookie 中复制 `SESSDATA` 的值。它只会发给本机的 `127.0.0.1` 服务，并且只在当前请求内存中使用；不要把它提交给别人或第三方网站。也可以用环境变量传入：

```bash
BILI_SESSDATA="你的SESSDATA值" npm start
```

抖音解析受限时，可以由用户明确勾选“本次从 Chrome 读取登录状态”；程序只把 `--cookies-from-browser chrome` 交给本机 `yt-dlp`，不会把 Cookie 写入笔记、任务或日志。如果链接仍无法读取，可以在播放器区域拖入本地 MP4、MOV、WebM、MP3、M4A 或 WAV 后继续。

B站和抖音的网页、播放器及访问策略都可能变化。请只处理自己有权访问和使用的视频，并遵守对应平台的服务条款与版权规则。
